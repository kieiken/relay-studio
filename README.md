# Relay Studio — ローカルアルファ 0.1.4

ひとつの共通原稿と、媒体ごとの個別原稿を管理する独立した投稿スタジオです。原稿・接続キー・配信設定はこのアプリ専用の保存先で管理します。AIによる掲載原稿の生成機能はありません。

実行用ZIPは [GitHub Releases](https://github.com/kieiken/relay-studio/releases) からダウンロードしてください。「Source code」は開発用です。

## AIに任せてインストール

ZIPを展開し、CodexまたはClaude Codeでフォルダを開いて「INSTALL_WITH_AI.mdを読み、インストールしてください」と依頼します。[詳しい案内（日本語・繁體中文）](INSTALL_WITH_AI.md)。環境・全ファイルのハッシュ検証、本体設置、既存データ保持、更新時の旧版退避、外部投稿をしない診断をまとめています。Node.jsの自動導入やChrome拡張の導入はこの版には含みません。

## 起動

macOSとNode.js 22以降が必要です。`start.command` を開くか、このフォルダで `npm start` を実行し、[Relay Studio](http://127.0.0.1:8792) を開きます。起動したターミナルは開いたままにしてください。閉じると予約実行・反響取得も停止します。配布ZIPは依存ライブラリを同梱しています。ソースだけ取得した場合は先に `npm ci --ignore-scripts` が必要です。

初回は接続・初期設定を表示します。６媒体すべて選択済みで、既定の投稿先を保存できます。媒体への接続を後回しにして下書きを作れます。

1. Facebook・Threads・Instagramに、自分のアカウントIDと利用可能なアクセストークンを設定し、接続テストします。初版は利用者自身の開発者アプリとアクセストークンを使う方式です。Facebookにはページ用トークン、InstagramにはInstagram Loginのプロアカウント用トークンを使います。
2. 共通原稿にタイトル・本文・公開画像URL・リンクを入力します。タイトルはnote／RedNote用で、他媒体の本文へ勝手に挿入しません。投稿先のチェックは初期設定を引き継ぎます。
3. 媒体カードの「個別に編集」で独立した原稿に切り替えます。初回に共通原稿をコピーし、共通へ戻しても個別原稿を保持します。再び個別へ切り替えると復元されます。
4. 通常は「今すぐ」のまま、主ボタンを一度押します。保存と全選択先の検証を経て、API媒体は配信待ち、手動媒体は未投稿の作業として登録されます。API媒体は起動中のワーカーが15秒間隔で処理します。自動媒体のみなら「今すぐ投稿」、混在なら「投稿する・手動分を準備」と表示します。選んだ媒体を黙って除外しません。
5. 予約したいときだけ「日時を指定」へ切り替え、「配信内容を確認」→「配信・作業予定を登録」で内容を固定します。即時・予約とも、下書きを後で変更しても登録済み予定は変わりません。未送信予定を取り消してから再登録できます。既に公開・結果未確認の記録が残る原稿は再登録できません。
6. 公式画面の媒体は、配信一覧→詳細から本文・タイトルをコピーして、公式画面で素材を添付し公開します。公開URLと実公開日時を照合して記録します。
7. 反響は媒体ごとに閲覧できます。取得不能は未取得のまま。公式画面から取得日時・期間・出典とともに手動記録することもできます。

## UI言語

画面上部の言語メニューから「日本語」と「繁體中文（台灣）」を切り替えられます。初期設定・原稿作成・配信・反響・確認ダイアログ・エラー表示が切り替わります。設定はこのブラウザに保存され、次回起動時も引き継がれます。ブラウザの保存機能が無効な場合は、そのセッション内のみ反映します。

投稿のタイトル・本文・個別原稿・アカウント名・入力中のキーは翻訳しません。言語切り替えだけでは設定や原稿を送信せず、予約の実時刻とタイムゾーンも変更しません。

## 初版の対応範囲

| 媒体 | 配信 | 反響 |
|---|---|---|
| Facebook | ページへの公式APIテキスト投稿。画像付きは未対応 | 公式API、取得不可項目は公式画面から記録 |
| Threads | 公式APIテキスト投稿。画像付きは未対応 | 公式API |
| Instagram | 公式API画像投稿。公開HTTPSのJPEG画像が必要 | 公式API |
| X | 本文コピー＋公式画面。公開操作は利用者 | 公式画面から記録 |
| note | タイトル・本文コピー＋公式画面。公開操作は利用者 | 公式画面から記録 |
| RedNote | タイトル・本文・画像URLの準備＋公式画面。素材添付と公開操作は利用者 | 公式画面から記録 |

共通画像があるとFacebook／Threadsには「この媒体だけ本文を引き継ぎ、画像を外す」を表示します。画像を黙って落としません。初版は画像URL方式で、端末の画像・動画のアップロードや素材ホスティングは含みません。

同じ予定日時で媒体別キューを作り、順次実行します。複数媒体で秒単位の同時公開は保証しません。ローカルキュー登録は媒体側の予約完了ではありません。Metaの実行時権限・素材条件を満たさなければ停止します。

## 反響の記録

- 基準は実公開日時＋48時間。48〜54時間に取れた実測を48時間観測とします。54時間を過ぎた場合は現在累計とし、過去の48時間値と扱いません。
- 初版の自動取得はMetaの期限到来分を一度取得します。失敗時・部分取得時に同じ要求を無限再試行しません。取得できない項目は公式画面で補完できます。
- 欠測は空欄／「—」、確認できた0は0。指標・取得元・日時・期間・公開後の経過時間を残します。
- 取得履歴を追記保存し、同じ媒体でも48時間観測と現在累計を区別して表示します。
- Facebookのリアクションと他媒体のいいねは同一指標として合計しません。横断ランキングも作りません。

## データとキー

- 原稿・予定・結果：`~/Library/Application Support/Relay Studio/studio.json`。データフォルダは利用者だけが読み書きできる権限で作成します。
- キー：macOSキーチェーンのアプリ専用サービス。既存HDSL用のキーチェーン項目は読みません。キーをJSON・配布ZIP・ブラウザstorageに保存せず、HTTP応答にも返しません。
- 接続を解除する前に、その媒体の予約と未確認結果を整理してください。解除で専用キーも削除します。
- アプリは127.0.0.1のみで待受。Host／Origin／Fetch Metadata／リクエストトークンを検証します。複数利用者向けの公開Webサーバーではありません。
- 設定→自動実行の一時停止で配信・自動反響取得を止めます。進行中の送信は取り消せません。
- 停止からの復帰で予定が15分以上過ぎていたら自動追い付き配信をせず、理由を記録して停止します。
- 送信中に終了した場合は結果未確認として復帰します。公開IDが分かれば公式APIで照合、分からなければ公式画面で確認。自動再送しません。
- バックアップはアプリ停止後にデータフォルダをコピーしてください。キーチェーンの秘密はバックアップに入りません。

## 検証・配布

`npm test` で、原稿切替・不変の配信内容・二重登録防止・投稿先照合・スケジュール・結果不明の再送防止・反響48時間判定・CSRF等をテストします。2026-09-22に既存の利用者アカウントで、Facebook・Threads・Instagramは本アプリの配信エンジンと公式API、X・note・RedNoteは公式画面を使った実投稿・照合・削除を実施しました。これは特定アカウントでの動作検証であり、全媒体の無人自動投稿、48時間後の反響取得、他利用者の認証まで実証したものではありません。キー保存の実OS動作と、各利用者のAPI権限は初回接続時に実機確認が必要です。

`npm run package` で実行用ZIPを作成します。固定した許可リストだけを含め、投稿履歴・接続情報・レビューの生ログ・開発環境の個人パスを入れません。今回のZIPはNode.jsを必要とするローカルアルファです。

一般消費者向けの販売完成版とする前には、配布アプリの接続方式（OAuth導入や利用者自身のアプリ設定のサポート範囲）、各媒体の提供条件、署名／インストーラ／更新機構、画像・動画素材配信、X／note／RedNoteの無人実行方式を別途仕上げる必要があります。現状を「全６媒体の完全無人投稿対応」と表示しないでください。

設計と完成画面は契約済みClaude Codeの `claude-fable-5` で２回レビューし、主要指摘を反映しています。詳細は [DESIGN-REVIEW.md](DESIGN-REVIEW.md)。
